## 0. 一句话目标与边界

保留 LuminaWatch **当前实际可用的功能、数据和业务规则**，把所有可见界面与页面层级重新设计成用户提供录屏里的 Apple Watch iPhone App **白色版本**：以“我的手表”为中心，底部是“我的手表 / 表盘图库 / 发现”三个一级入口；大标题、真实比例的表盘展示、分组列表、克制的层级和轻盈的浮动导航构成统一语言。当前那些大面积渐变、厚重阴影、每张卡都加毛玻璃、巨大空白和随意排版均应重做。

“一比一”指**能对应的页面，按录屏逐帧核对信息顺序、比例、对齐、留白、导航和交互**；不是复制 Apple 的商标、图标、表盘图片、产品文案或 iPhone 系统状态栏。Apple Watch App 没有“小云聊天、心情日历、关怀时间线”等页面，这些不能声称有原页可照抄，应使用**同一套白色 Apple Watch App 组件规则**做原创延展。Android 系统返回、状态栏、无障碍和安全区仍须符合 Android。小云品牌形象继续保留。

本阶段是**纯视觉、交互和信息架构重设计**，不接入蓝牙、真实传感器、云端对话或手表同步，也不把演示能力写成真实能力。

2. 对同一宽高的当前 Android 页面留存截图；建立页面目录和入口清单。`docs/screenshots/` 是旧版参考，不代表新设计目标。
3. 核查 `README.md`、`app/Navigation.kt`、`app/AppShell.kt`、`data/Models.kt`、`data/AppStore.kt`、全部 `feature/` 页面、`ui/` 组件。记录基线构建状态、已存在用户数据键和已知缺陷。**不要先删除或重置任何数据。**
4. 先交三张一级页面的静态线框/视觉稿，再交关键二级页（设备设置、健康、心情三步、日历、聊天、闹钟）样稿；用户确认后才逐批改代码。若 DeepSeek 收到“直接实施”的明确指令，可按第 8 节分期施工，但每期仍要保留可运行状态。

## 2. 信息架构：三栏承载全部既有功能

| 一级页 | 按 Apple Watch App 录屏重做的内容顺序 | 现有功能入口 |
|---|---|---|
| **我的手表** | 顶部手表/绑定状态 → 大标题“我的手表” → “我的表盘”横向预览 → 手表设置的分组列表 | 设备状态、连接与同步、闹钟、小云形象、个人与隐私；健康/心情/小云/关怀可放独立“健康与陪伴”分组，但不挤入表盘区域 |
| **表盘图库** | 大标题 → 高质量表盘大图 → 横向可滑动分类/表盘 → 选中预览/说明 | 现有纯白、珊瑚、深色 3 款手机端预览主题；保留已选状态及本地持久化，不伪造庞大的可同步表盘库 |
| **发现** | 大标题 → 内容型入口与清楚的分组，不做工具按钮九宫格 | 今日总览、健康、心情月历/记录、心理问卷、小云聊天/记忆/风格、关怀/规则；每个核心功能最多 2 次点击可到达 |

三个一级页保留独立滚动位置和状态。进入二级页使用统一顶部返回；返回时回到来源页，不跳到另一 tab。底栏只用于一级导航，不把“记录心情”之类的动作混进 tab。键盘弹出时输入栏不被遮挡。旧 `TodayOverview/HealthHome/ChatHome/CareHome/DeviceHome` 仍在，但需全部重绘，不能只是把旧页面藏在新入口后面。

## 3. 白色视觉系统（先做 Token，再做页面）

以下是**初始施工 Token**，最终数值要对用户视频同尺寸截图逐项微调，不可把表格当已量测的 Apple 原值。

| 类别 | 初始规则 |
|---|---|
| 页面底 | `#FFFFFF` 主背景；分组区 `#F2F2F7`；内容表面 `#FFFFFF`。**不做全屏蓝/绿渐变**，心情记录沉浸区例外 |
| 文字 | 一级 `#1C1C1E`、二级 `#636366`；中文优先系统字体；标题约 32–34sp，分组标题 20–22sp，行标题 16–17sp，说明 13–15sp。允许字体放大 |
| 强调色 | 手表/表盘操作用暖橙，通用链接可用蓝色；仅作为选中/操作标记，不把整张列表卡染色。心率红、血氧青蓝、心情随状态变化 |
| 间距 | 页面左右约 20dp（小屏 16dp）；4/8dp 网格；组间 24–32dp；普通设置行 52–64dp；按参考截图微调 |
| 形状 | 分组容器圆角约 14–18dp；表盘预览按手表真实比例；浮动控件才用胶囊。不要每层都嵌套 24dp 大圆角卡 |
| 边界与阴影 | 内容分组优先用底色差与 1px 分隔线，阴影仅浮层轻微使用。日历格边界要可见，不能靠几乎透明的描边 |
| 图标 | 一套统一尺寸/线宽的本地或开源矢量图标；不直接复制 Apple/SF Symbols 私有资产，不用 emoji 当系统图标 |
| 按钮 | 页面只保留一个主 CTA；普通行为文字/列表行表达。**无大面积黑底 UI**；心情流程的底部 CTA 跟随当前情绪色相，保证白字或深字有对比度 |

### 页面模板

- **一级页**：状态栏安全区 → 大标题（滚动时可收敛）→ 关键视觉/内容 → 分组列表 → 底部浮动三栏。背景与内容不拼接花哨装饰。
- **设置类二级页**：小标题导航栏/返回 → 分组标题 → 白色组内连续行/分隔 → 组尾说明；危险操作单独分组。
- **数据详情页**：标题 → 核心数据与单位/来源 → 时间范围 → 图表 → 统计与说明；图表本身不用玻璃。
- **沉浸流程页**：固定顶部步骤与返回 → 主视觉 → 当前选择文字 → 单一操作区 → 固定底部 CTA。不同步骤的云图、标题和 CTA 基线一致。
- **长列表页**：页面级纵向滚动；仅表盘库、小云形象允许明确的横向滚动，不制造纵横手势冲突。

## 4. 玻璃与动效：从“全页材质”收敛成“导航材质”

用户当前不满意的大块毛玻璃卡、强折射、高饱和渐变和厚阴影，应全部取消。按 Apple 的材料层级，**玻璃仅服务于导航/浮动控制，普通内容使用实体或系统分组材料**。优先检查当前 `ui/BackdropGlass.kt`、`ui/GlassBottomBar.kt`、`ui/GlassSegmented.kt` 和各页对玻璃的引用，做一张“保留/替换/删除”清单，不要先全局替换导致触控或崩溃。

| 允许玻璃 | 不允许玻璃 |
|---|---|
| 底部三栏悬浮容器、必要的短暂浮动工具栏/弹窗；滑块当前抓手可有极轻高光 | 设置行、健康数据卡、图表、日历所有日期、长列表所有项目、长文说明 |

玻璃需要真实背景采样时才用 Backdrop；纯白背景上不必为了“液态”强行折射。当前工程使用 Backdrop **1.0.2**，不要按照技能包的 2.0.0 示例直接复制 API；若要升级，先独立核查 `compileSdk/Kotlin/AGP/minSdk` 兼容性并说明迁移成本。Android 12 以下有实体/半透明降级；大字/减少透明度/减少动态效果下可读。玻璃上叠玻璃避免循环背景捕获。列表项不各自创建 GPU 图层。

动效只表达操作关系：表盘横向滑动跟手、页面进退方向一致、情绪云随滑块实时变化并低幅呼吸、选择状态 150–300ms 过渡；可中断；屏幕阅读器与减少动态效果可用。**不要用持续闪光、彩虹折射、每张卡漂浮来替代排版。**

## 5. 数据与功能保护线

现有 `AppStore` 采用 SharedPreferences + JSON，心理问卷还使用 `AssessmentVault`。**本次不改存储格式、不重置数据、不换包名/签名、不以迁移为由清空记录。**如果必须调整模型，先写向后兼容读取和数据迁移测试。以下至少逐项回归：

1. 闹钟已有 x/15 条、新增/编辑/开关/删除/撤销；第 16 条不能保存；本机保存不等于手表响铃。
2. 心情三步填写、从月历指定日期新增、同日多条、保存后日期格与下方列表即时更新、详情/删除、重启仍在。
3. 小云形象全套可横向浏览/选择并持久化；3 个表盘预览主题选择持久化；两者不能混成一个字段。
4. 小云对话文字/图片、会话历史、记忆/风格与关怀事件上下文授权；本地规则回复仍标注演示。
5. 心率、血氧与活动数据有清楚来源；Debug 固定预览值不在 Release 冒充测量；无设备时明确空态。
6. 关怀事件已读/回访/删除、规则与隐私偏好；问卷得分和历史保持可用。
7. 本地设备 ID 绑定/解绑/同步状态不伪装真实连接；家人共享只显示实际本地偏好。

任何“目前尚未同步至手表 / 尚未连接 / 仅本机演示”的提示在新 UI 中要更清楚，不能为模仿 Apple 隐藏。不得加入没有后端和硬件支持的假搜索、假同步、假表盘下载、假健康实时图。

## 6. 可直接给 DeepSeek 的实施顺序

**阶段 A：确认稿，不改代码。** 抽视频帧并标尺寸；做三张首页 + 至少六类关键二级页的同尺寸静态视觉稿，标注每个按钮通向哪里、旧功能落在哪里。用户确认后进入 B。

**阶段 B：设计系统/外壳。** 建语义化颜色、文字、间距、圆角、图标、分组行、导航栏和三栏底栏组件；先让“我的手表 / 表盘图库 / 发现”三页与录屏对齐。沿用现有路由和数据接口，不重写业务逻辑。交付三页前后对比截图。

**阶段 C：逐族重绘二级页。** 顺序建议：设备/闹钟/形象表盘 → 今日/健康 → 心情流程/月历/问卷 → 小云聊天/记忆/历史 → 关怀。每一族都要列全页截图和功能回归表；不要只重绘首屏。

**阶段 D：玻璃和动效。** 在静态版获得认可后才调折射/模糊与动画；视觉不清楚时立刻退回实体材料。每个功能界面可关闭特效且仍可操作。

**阶段 E：整体验收。** 同视口截图与视频关键帧逐项对照，逐页修正标题/表盘大小/行高/留白/底栏；测试低/高 DPI、字体放大、系统返回、横竖屏、小屏、安全区、键盘、深层返回、API 26/31/33+；构建 Debug APK 并记录构建结果。不要未经实际构建宣称已完成。

每期报告固定格式：`本期完成页面 / 对照参考帧 / 改动文件 / 功能回归 / 未通过项 / 下一期`。若依赖视频中看不清的细节，列出截图和时间点求用户确认，不自行“发挥”。

## 7. 最终验收清单

- [ ] 三个一级入口的**版式**与参考视频白色化后逐项对齐，而不仅是改颜色或改底栏。
- [ ] 所有二级页都换成统一新设计；旧渐变/旧大玻璃卡/厚阴影不再残留。
- [ ] 第一眼看出“管理手表”：手表状态、表盘、设置顺序清楚；但小云/健康/关怀/心情入口可找。
- [ ] 心情三步各为独占阶段，云会动；保存后对应日历日期显示缩略图和记录；按钮颜色随情绪页变化。
- [ ] 玻璃只在有限的浮动交互层出现，文本和数据始终可读；旧版丑陋玻璃不是换个颜色继续使用。
- [ ] 当前所有路由都有入口、可返回、可点击；无死按钮；切换一级页保留状态。
- [ ] 闹钟上限、数据持久化、表盘和形象选择、问卷结果、聊天与关怀均通过回归。
- [ ] 演示/未连接/未同步边界不被美化掩盖；健康与心理结果无诊断式表述。
- [ ] 字号放大、TalkBack、48dp Android 触控区、颜色对比、低动态与 API 降级可用。
- [ ] 有同尺寸前后截图、参考视频帧对照、APK 构建日志和未完成清单。
