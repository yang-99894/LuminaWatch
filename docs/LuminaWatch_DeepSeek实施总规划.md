## 0. 给执行者的总要求

用 Kotlin + Jetpack Compose 在**现有 LuminaWatch 项目上迭代**，不要另起一个项目，不要把页面换成 WebView/Flutter/React Native。保留现有包名 `com.pointerwander.luminawatch`，先跑通当前工程并记录基线，再逐阶段修改。每完成一个阶段必须能编译、安装和实际操作，向用户说明改了哪些文件、演示能力与真实能力的界限、怎样验证。

优先级是：**页面结构与交互成立 → 五段可拖动玻璃底栏 → 健康/对话/关怀/情绪/闹钟闭环 → 视觉与资产打磨 → 接口预留与回归**。不要把大量时间先花在装饰性动画上。

禁止直接复制苹果健康、小米运动健康或 Claude 的图标、图表、文案和布局；借鉴它们的信息层级、可读性与暖色气质。复用本地项目代码和小云资产时核对出处及许可证，保留上游要求的授权声明。不要在源码、日志、截图或文档里泄露密钥、真实设备 ID 或健康隐私数据。

## 2. 交付边界和阶段定义

### A 阶段：可交互原生前端（本轮要完成）

- 页面、导航、玻璃、图表、情绪云、角色形象、关怀记录、闹钟上限、绑定流程都能真实操作。
- 健康数据和手表连接用明确标识的演示场景；能切换“已连接/离线/无数据/健康变化”，并能看见页面响应。
- 对话允许文字输入、演示回复、历史会话和健康事件上下文的本地模拟；语音仅在有真实能力时启用，否则提供有解释的禁用态。
- 闹钟和心理记录在本机持久化。闹钟不会在真实手表/系统触发；同步状态展示为“未连接手表/待接入”，不能虚构“已同步”。
- 关怀的演示触发由场景控制或演示样本驱动，明确标识“演示事件”。

### B 阶段：真实能力接入（另行启动，需先核对协议）

- 手表配对、唯一 ID 校验、数据同步、闹钟下发、心率/血氧读取、事件推送与手表震动。
- LuminaAndroid 对话协议、鉴权、SSE、会话历史与语音链路。
- 云端记录、账号映射与跨设备同步。

接口尚未核实的功能不允许在 A 阶段写死伪协议或虚构服务端字段。把数据来源抽象出来，UI 通过接口获取 `Demo` 实现；B 阶段接入时替换实现。

### 不在当前 APP 主范围

摔倒检测模型、老人连续心率监护、家属自动告警及紧急求助只作为比赛 PPT 的未来扩展。当前演示不得把它们显示为已工作的功能。

## 3. 信息架构与导航

### 3.1 五个一级页面

| 位置 | 名称 | 首屏主要内容 | 常用去向 |
|---:|---|---|---|
| 0 | 今日 | 小云问候、今日摘要、心率/血氧最近值、下一闹钟、连接状态、最近关怀 | 指标详情、闹钟、关怀、小云 |
| 1 | 健康 | 心率、血氧、心理状态入口、近期趋势与异常事件 | 心率/血氧详情、记录心情、心情月历 |
| 2 | 小云 | 对话消息、角色形象、快捷发起、语音入口状态 | 会话历史、健康事件上下文、情绪记录 |
| 3 | 关怀 | 待处理关怀、事件时间线、回访、关怀规则 | 事件详情、续聊、设置 |
| 4 | 设备 | 手表卡、唯一 ID、闹钟、形象、表盘、其他设置 | 绑定、闹钟列表、形象选择、皮肤选择 |

底栏顺序固定为 `今日 / 健康 / 小云 / 关怀 / 设备`，这五项都能通过点击或拖动到达，不设第六项。“小云”是完整的一级页面，用户从任何一级页点中间即可进入，不再需要从首页点按钮后进入一个隐藏底栏的聊天二级页。

### 3.2 二级页面与返回

| 入口 | 二级页 | 返回位置 |
|---|---|---|
| 健康、今日 | 心率详情 / 血氧详情 | 返回发起页，并恢复该页滚动位置 |
| 健康、今日、小云 | 心理状态记录 / 月历 / 日详情 | 返回发起页，保留尚未提交的填写内容直到明确取消 |
| 关怀、今日 | 事件详情 / 关怀规则 / 安静时段 | 返回关怀或发起页 |
| 设备、今日、小云确认卡 | 闹钟列表 / 编辑 | 返回原入口，保存成功后关联卡刷新 |
| 设备 | 绑定 / 小云形象 / 手表皮肤 / 设置 | 返回设备 |
| 小云 | 历史会话 / 对话隐私设置 | 返回当前会话 |

二级页默认隐藏底栏，使用 Android 系统返回手势及统一顶部返回。不同一级页之间切换不叠加无限返回栈；按系统返回键从二级页返回来源一级页，从一级页按 Android 常规返回行为处理。键盘弹出时底栏隐藏或避让，消息输入框始终在键盘上方；返回键先收键盘。横向图表滑动不能抢夺系统边缘返回手势。

## 4. 最关键组件：五段式可拖动液态玻璃导航

### 4.1 视觉定稿

- 一条悬浮玻璃胶囊，左右留 12–20dp 安全边距；高度约 64–72dp，适配系统底部手势区。
- 五个**等宽**标签。图标上、文字下，点击热区至少 48dp。中间小云图标可更大，但锚点宽度不能变。
- 一枚玻璃选中滑块沿五格连续移动。选中普通页时使用浅暖玻璃、深色文字、陶土色小强调；到中间小云时渐变为近黑色，白色云图标与文字。黑色只在小云选中态及少数主按钮出现。
- 胶囊、滑块有实际背景采样/模糊/折射/高光。页面数据卡不用大面积玻璃。
- 深色模式保留主题适配：颜色对比成立，黑色小云滑块要与深色背景有轮廓区分。

### 4.2 手势和状态机

定义 `selectedIndex`（已提交页面）、`dragValue`（0f..4f 连续预览值）、`isDragging`、`previewIndex`。唯一有效的页面索引是 `selectedIndex`，拖动过程不能触发五个页面反复组合/请求。

1. 点击任意格：设置目标索引，滑块弹簧运动，并正式导航一次。重复点当前项：今日/健康/关怀/设备回到该页顶部；小云保持当前会话并回到底部最新消息。
2. 按住当前选中滑块横向拖动：超过约 6–8dp 的水平触摸门槛才开始；滑块跟手；越过格子中心给一次轻触觉反馈；到左右两端即受限。
3. 松手：以最近格中心为目标吸附，吸附目标确定后**只提交一次**导航。取消、来电或手势被系统夺走时回到已提交索引。
4. 纵向移动优先、长列表滑动、键盘区域交互不能切换底栏。侧边系统返回热区优先于底栏拖动。
5. 点击与拖动同时发生时去重；旋转/尺寸变化后重新计算格宽并对齐选中项。
6. TalkBack 用户可以逐项点击，读出“第 n 个，共 5 个，已选中/未选中”；不能要求拖动才能使用。

默认交互是“拖当前选中滑块，点其他标签”。若设计评审后要求从轨道任意空白处直接拖动，可将手势识别提升至胶囊容器，但仍须先通过横向门槛并尊重各标签点击。

### 4.3 技术实现

- 引入 `io.github.kyant0:backdrop:2.0.0`；可根据实际编译结果决定是否显式引入 `io.github.kyant0:shapes:1.2.0`。参考 WanderIsland 的 `LiquidBottomTabs`、阻尼动画和按压高光，迁移后改成本项目主题与五个标签。
- 页面内容用 `rememberLayerBackdrop` / `Modifier.layerBackdrop` 建立采样源，底栏作为被采样内容的兄弟浮层；不能让底栏采到自己。
- 玻璃容器、隐藏标签层和选中滑块采用三层结构；滑块可用 `rememberCombinedBackdrop` 组合背景和标签。效果顺序为色彩处理 → 模糊 → 折射。
- 玻璃内再叠玻璃时使用 `exportedBackdrop`，避免循环绘制。不要把技能包的 `effects/`、`backdrops/` 源码副本和 Maven 库一起复制，防止重复声明。
- Android 13+ 使用完整折射/交互高光；Android 12 使用支持的模糊和高光；Android 11 及以下使用可读的实体半透明备选。当前工程 `minSdk 26`，必须覆盖这三档。
- 目前 `NativeLiquidGlass.kt` 通过 Android View 截图采样实现自定义玻璃。迁移底栏时不让旧截图采样与新 Backdrop 在同一区域叠加。确认新方案稳定后，删掉无引用的旧实现；若旧组件仍用于别处，明确其使用边界。
- 迁移参考组件时检查 Kyant 上游和 WanderIsland 源文件的许可信息，项目内保留适用的许可证及版权声明。

### 4.4 底栏完成标准

五项连续可达；小云处于正中央；从 0 拖至 4 不需要经过独立按钮；按住时滑块跟手、松手吸附；纵向滚动不误跳页；频繁切换无闪屏、无残留玻璃影像、无后台崩溃；API 26/31/33+ 下功能均可用。至少在真机或模拟器上录制一次完整 0→4→2 的操作验证。

## 5. 每个页面要实现什么

### 5.1 今日

按“问候 → 下一步 → 身体数据 → 关怀 → 设备状态”排序：顶部当天日期及小云表情；关怀卡只显示当下最重要的一条；心率和血氧最近测量分别展示数值、单位、时间、来源；下一闹钟卡显示时间和开关；设备卡显示连接、电量、最后同步。没有设备时提供绑定入口；无有效健康数据时显示引导文案，不用 `0` 伪装读数。所有卡片能通向对应详情。

### 5.2 健康总览与详情

总览固定先显示心率、血氧，再显示心理状态和近期事件。心率强调色为克制珊瑚红，血氧为青蓝；主背景白色/暖灰。大号数值、单位、测量时间、设备来源同屏可见。参考 Apple Watch 的信息清晰度，图形、图标和排列自己设计。

详情采用“最近值 → 日/周/月/年液态分段滑块 → 可拖动趋势图 → 范围统计 → 小云解释/复测建议 → 数据说明”。分段滑块支持点选、抓住选中块滑动、吸附；图表支持横向拖动读取某个真实存在的数据点及时间。心率日视图可用散点/区间，血氧必须按离散测量点展示，不能画成无依据的连续监测。无数据、无效数据、离线、只有 1 个点都要有完整状态。

演示版中的“偏高/偏低”只说明演示规则，不能当成医疗诊断；提醒不能仅凭单个演示点自动宣布疾病或紧急事件。正式规则在 B 阶段通过可配置阈值、数据质量、持续时长、个人基线和专业评审确定。

### 5.3 小云对话

作为中间一级页：顶部小云形象与会话历史，主区域消息列表，底部文本输入/发送/语音入口状态。空会话时显示角色、三个入口“陪我聊聊 / 记录心情 / 看看今天状态”。消息需要发送中、回复中、失败重试、空记录四种状态。切换其他一级页后再回来，当前会话保留。

由关怀事件进入时，在对话上方展示健康上下文卡，列明事件时间、数据来源、读数是否为演示、是否允许小云使用该上下文；未授权时默认不传任何健康数据。对话消息和关怀事件分别存储，不能混为一张列表。A 阶段使用可复现的本地回复，并始终标注“演示回复”；B 阶段才通过 LuminaAndroid 现有协议接入流式回复、鉴权与历史记录。

### 5.4 关怀

关怀首页包含“待处理 → 时间线 → 规则入口”。事件至少分心率变化、血氧变化、心理状态、久坐、闹钟/提醒、手动关怀。每条事件呈现触发来源、时间、使用的数据、手表动作（若仅演示则写明）、用户回应和状态。详情允许继续聊天、标记已处理、设置回访或关闭同类提醒。安静时段、震动偏好、AI 读取健康上下文授权都应能改动且持久化。

A 阶段提供“演示心率变化”和“演示血氧变化”的触发入口，供比赛演示一键走通：事件出现 → 小云关心 → 对话上下文 → 回访记录。触发入口可放在演示设置里，避免正常用户误以为设备实时检测成功。

### 5.5 心理状态与情绪云

入口置于健康总览、今日摘要和小云空状态。流程：选择“此刻/今日” → 拖动连续情绪轴 → 选择 1–3 个情绪词 → 选择影响因素 → 可选短文字 → 确认保存 → 月历/单日详情可见 → 可选择带着该记录和小云聊天。保存前可返回修改；保存后允许编辑和删除。

原创主视觉是**情绪云**，不是 Apple 花朵：采用 `androidx.graphics:graphics-shapes:1.0.1` 的 `RoundedPolygon`/`Morph` 和 Compose Canvas，云朵轮廓、层次、色温与轻微呼吸随情绪值变化。形状与文字标签共同表达，不靠颜色判读。拖动时跟手变化，月历格子采用静态缓存图形；系统减少动态效果时停止循环动画。不得用情绪记录推断心理疾病。

### 5.6 闹钟

完整管理入口放在设备页，今日只放下一闹钟快捷卡，小云通过自然语言提出创建时必须转为结构化确认卡。闹钟模型至少包含 ID、时间、重复星期、标题、启用状态、声音/震动、小云播报偏好、创建时间、同步状态。

**最多 15 条已存在闹钟，关闭的也占名额**。列表始终显示 `x/15`；第 16 条在保存层拦截，不只禁用按钮；编辑旧闹钟不占新名额；删除后才释放名额，支持短时间撤销。A 阶段在本机保存并显示“尚未同步至手表”；不申请系统闹钟权限、不声称会在手表响起。B 阶段才实现下发、确认、失败重试、设备冲突处理。

### 5.7 设备、唯一 ID、形象与表盘

设备页首卡显示绑定状态、电量、同步时间；未绑定时显示扫码/手动输入唯一 ID 的入口。A 阶段使用带“演示绑定”标记的本地流程：输入 → 格式校验 → 确认设备信息 → 绑定结果。不可把任意字符串写成“验证通过的真实手表”；真实唯一 ID 的校验协议等待 B 阶段。解绑前二次确认并说明本地记录如何处理。设备 ID 默认脱敏显示。

“小云形象”管理聊天头像、对话空状态、关怀表情；“手表皮肤/表盘”管理手表 UI 预览，两者分开。先清点 LuminaCross 和 LuminaAndroid 的小云资源，选择高质量、透明、命名明确的静态图，建立状态映射；动画资源数量受控。白色小云需要暖灰背板或细轮廓。A 阶段选择可以改变 App 中的小云形象，表盘只展示可选预览和“尚未同步”状态。

## 6. 统一视觉与组件规格

| 元素 | 要求 |
|---|---|
| 色系 | 白色/暖白为主体；页面背景 `#F7F6F3`，表面 `#FFFFFF`，主文字约 `#1F1F1D`；陶土暖色约 `#D97757` 用于强调；高权重按钮与小云选中态用近黑 `#171716`。不以紫色作为品牌色 |
| 健康色 | 心率珊瑚红、血氧低饱和青蓝；警告另用琥珀/文字/图标，不把正常心率红色误认成警报 |
| 字体 | 中文系统字体；大数字启用等宽数字；正文通常 14–17sp，支持系统字体放大 |
| 图标 | 同一套圆角线性图标；选中允许填充；重要功能需图标+文字；不复制 Apple/Xiaomi 产品图标 |
| 卡片 | 数据区域白色实体卡或轻分隔；24dp 左右圆角；玻璃只用于导航、分段控制、少数浮层与输入区 |
| 动效 | 常规状态切换 150–300ms；拖动逐帧跟手；可被新手势打断；减少动态效果时关闭循环装饰动画 |
| 无障碍 | 触控区域至少 48×48dp；图标有内容描述；选中态、演示态、异常态都有文字；正文与背景达到适当对比 |

先建立 `WatchColors`/`WatchTypography`/`WatchShapes` 等语义化 Token，再改页面。现有 `WatchTheme.kt` 里 `lavender`、`violet` 实际已是暖棕色值，但名字与视觉意图不符；重命名或增加语义 Token，不要在各页面继续硬编码旧名字。暗色模式也要通过同一套语义 Token 生效。

## 7. 前端数据结构与接入接口

为了让 A 阶段演示和 B 阶段真实接入共用页面，至少定义以下模型与接口。字段可因现有代码调整，但语义必须保留。

| 模型/接口 | 必备信息 | A 阶段实现 | B 阶段替换 |
|---|---|---|---|
| `HealthSample` / `HealthRepository` | 指标类型、值、单位、测量时间、数据质量、来源 `DEMO/WATCH` | 固定可复现样本与空数据场景 | 手表读取、历史同步 |
| `WatchDevice` / `DeviceRepository` | 脱敏 ID、名称、连接、电量、最后同步、能力列表 | 演示设备状态切换 | 配对/绑定协议 |
| `ChatMessage` / `ChatRepository` | 会话 ID、角色、时间、发送/流式/失败状态、可选上下文授权 | 本地对话模拟 | Lumina 会话/SSE/鉴权 |
| `CareEvent` / `CareRepository` | 事件类型、触发原因、来源数据、状态、回访时间、用户回应 | 本地场景生成及持久化 | 手表事件和服务端记录 |
| `MoodEntry` / `MoodRepository` | 此刻/今日、连续值、情绪词、因素、备注、时间 | 本地持久化 | 可选跨端同步 |
| `Alarm` / `AlarmRepository` | 字段见 5.6、总数限制、同步状态 | 本地持久化与 15 条规则 | 手表下发及确认 |
| `CarePreferences` | 安静时段、触发类别、震动、健康上下文授权 | 本地设置 | 与手表/账号同步 |

选择 Room 保存闹钟、心理记录、关怀时间线和会话历史，DataStore 保存简单开关/偏好；若先做小步提交，可以先用 Repository 接口加本地内存实现，再换持久化，但最终 A 阶段必须通过重启验证闹钟、心理记录与设置不会丢。每张健康卡与事件卡显示数据来源。`DemoState` 可以保留为演示场景控制器，不再作为所有业务数据和 UI 状态的唯一容器。

## 8. 核心跨页流程（按此做联动）

### F1：健康变化与小云主动关怀

演示场景开关生成一条有时间和来源的心率/血氧事件 → 今日出现关怀摘要、关怀页出现完整记录 → 打开事件看到触发说明 → 用户选“和小云聊聊” → 中间小云页打开对应会话并展示健康上下文授权卡 → 对话后选择稍后回访或结束 → 关怀事件状态更新。未授权时消息中不得自动夹带健康数值。

### F2：心理状态记录

健康或今日进入记录 → 拖情绪轴，云形跟手变化 → 填词/因素 → 保存 → 回到健康看到当天摘要 → 月历可点开详情 → 从详情选择“和小云聊聊”，带经用户同意的记录摘要进入对话。

### F3：闹钟

今日、设备或小云确认卡进入闹钟编辑 → 校验时间/重复规则/15 条上限 → 本地保存 → 今日下一闹钟立即刷新 → 设备列表显示 `x/15` 和“尚未同步” → 删除后可撤销；第 16 条保存失败且说明原因。

### F4：设备与个性化

设备页进入演示绑定 → 绑定状态在今日、设备同步变化 → 选小云形象后聊天头像与关怀卡同步变化 → 选表盘后设备预览改变；同时明确表盘尚未下发手表。

## 9. 推荐代码组织和文件迁移

不要一次性重写所有页面。先搭结构、保持现有功能可运行，再逐页替换：

```text
app/src/main/java/com/pointerwander/luminawatch/
├─ app/             AppShell、一级导航、路由、主题与演示标识
├─ ui/glass/        玻璃底栏、可拖动分段控件、玻璃按钮/浮层
├─ ui/components/   小云头像、指标卡、状态卡、图标、空态
├─ feature/home/    今日
├─ feature/health/  总览、指标详情、图表
├─ feature/mood/    记录、情绪云、月历
├─ feature/chat/    小云对话、历史、上下文卡
├─ feature/care/    时间线、事件详情、规则
├─ feature/device/  设备、绑定、形象、表盘、设置
├─ feature/alarm/   列表和编辑
└─ data/            models、Repository 接口、Demo 实现、本地持久化
```

这只是建议组织方式，执行者可以沿现有文件增量拆分；不得为符合目录树而引入不必要的大规模迁移。推荐提交顺序：

1. 构建基线与页面路由：修正 `Page` 一级/二级关系，五入口可点击，所有旧入口不失效。
2. 主题和图标：暖白/陶土/黑色 Token，统一图标、状态样式。
3. 玻璃底栏：Backdrop 引入、五段拖动、兼容降级、系统手势与键盘验证。
4. 健康：心率/血氧详情与日周月年选择器、可读图表、空/离线/演示态。
5. 情绪：记录流程、云形 Morph、月历和本地保存。
6. 对话：一级页改造、消息状态、形象资源、事件上下文联动。
7. 关怀：事件/详情/偏好、演示触发闭环。
8. 闹钟/设备：15 条限制、本地保存、演示绑定、形象/皮肤预览。
9. 全量回归：五个流程、无障碍、尺寸与 Android 版本矩阵，清理旧玻璃与旧演示导航的无用代码。
