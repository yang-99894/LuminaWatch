# LuminaWatch 产品与 UI 设计方案

> 文档状态：方案评审稿 v1.1；实施以《LuminaWatch_DeepSeek实施总规划.md》为准  
> 适用项目：LuminaWatch（Android 原生应用，Kotlin + Jetpack Compose）  
> 本轮范围：只确定产品结构、页面层级、视觉和交互，不修改现有 APP 代码。  
> 参考边界：吸收 Apple 健康/Apple Watch 的信息组织方式、小米运动健康的设备管理思路与 Claude 的暖色气质，不复制其页面、图标或品牌资产。

## 1. 产品定位

LuminaWatch 不是单纯的手表管理器，也不是把健康数据堆成仪表盘。它的核心定位是：

**一个能感知身体变化、主动发起关心、持续陪伴并帮助用户记录身心状态的“小云”AI 手表客户端。**

产品最有辨识度的闭环：

```text
手表感知身体变化
        ↓
小云在手表端震动并发起简短询问
        ↓
用户用快捷选项或语音回应
        ↓
进入小云 AI 对话，结合当时心率/血氧上下文交流
        ↓
生成一次关怀记录或心理状态记录
        ↓
必要时设置稍后回访、提醒或闹钟
```

这条链路把健康、对话、关怀、心理记录和提醒串成一个整体，而不是五套彼此孤立的功能。

## 2. 底部导航最终建议

采用 **5 个底部一级入口**，不再继续增加。中央固定为“小云”，并作为全局最重要入口。

| 顺序 | 一级入口 | 主要职责 | 不放入的内容 |
|---|---|---|---|
| 1 | 今日 | 今日摘要、下一闹钟、手表状态、最近关怀和快捷入口 | 完整历史和复杂设置 |
| 2 | 健康 | 心率、血氧、心理状态、趋势与记录 | 设备连接和皮肤管理 |
| 3 | 小云 | AI 对话、语音交流、主动关怀续聊 | 数据仪表盘和设置列表 |
| 4 | 关怀 | 主动关怀时间线、触发原因、回访、关怀规则 | 普通聊天记录 |
| 5 | 设备 | 绑定唯一 ID、同步、闹钟、形象/皮肤、设备设置 | 健康趋势详情 |

### 为什么是 5 个

- Android 主流底部导航建议不超过 5 项；当前五类任务的使用目的彼此明确。
- “小云”位于中央后，用户任何时候都能快速进入对话，符合产品核心定位。
- “健康”和“关怀”必须分开：健康回答“我的数据怎样”，关怀回答“小云为什么关心我、后来发生了什么”。
- “闹钟”是手表能力管理，不需要单独占一个一级入口；在“今日”提供快捷卡片，在“设备”提供完整管理。

### 底部导航交互

- 整体为悬浮液态玻璃胶囊，左右保留安全边距，适配 Android 手势导航区。
- 选中指示器必须支持 **点击切换 + 横向拖动 + 松手吸附**，而不是死板点击。
- 拖动过程中指示器实时跟手，越过标签中心线时给一次轻触觉反馈。
- 五个标签都位于同一条等宽、连续的玻璃轨道。中央“小云”保持第 3 个锚点，采用更醒目的云朵图标；滑块选中小云时转为黑色、图标文字转白，并有极轻陶土色光晕。小云不从可拖动轨道中拆为独立按钮。
- 从当前选中滑块横向拖动可预览五个标签，松手吸附到最近标签后再切换页面；点击任一标签直接切换。竖向滚动时不得误触导航拖动。
- 其他四项使用统一线性图标与文字；选中状态用黑色文字和暖橙小标记，不把整栏染橙。
- 点击与拖动均可完成相同操作，保证无障碍与可发现性。
- 玻璃只用于导航容器和滑动指示器；列表卡片仍使用实体白色表面，避免性能和可读性问题。

## 4. 五个一级页面设计

### 4.1 今日

目标：用户 5 秒内知道“小云是否在线、今天身体怎样、接下来有什么事”。

首屏顺序：

1. 顶部问候：日期、简短问候、小云当前形象。
2. 小云关怀卡：有事件时显示“刚才心率变化有点明显，要聊聊吗”；无事件时显示轻量陪伴话术。
3. 下一闹钟：时间、标签、开关和“查看全部”。
4. 健康双卡：心率与血氧只显示最近值、状态与更新时间。
5. 今日心理状态：未记录时给单一入口，已记录时展示当天情绪符号和一句摘要。
6. 设备状态：电量、连接、最近同步时间。

今日页不放长图表，不放大量设置，避免成为杂乱入口页。

### 4.2 健康

总览采用“重点数据 + 可编辑关注项”的结构：

- 顶部显示“今日健康概览”，不使用彩虹式大仪表盘。
- 第一行固定为心率和血氧，保证手表现有能力优先。
- 第二部分是心理状态与近期趋势。
- 后续能力用“更多健康数据”折叠展示，未接入的数据明确写“暂未支持”，不制作假数据。
- 异常状态用图标、文字和颜色同时表达，不能只靠红色。

### 4.3 小云

复用 LuminaAndroid 的对话能力与后端接口，但重新组织为适合手表陪伴场景的 Compose 页面。

页面结构：

- 顶部：小云头像、在线/同步状态、历史会话入口。
- 中部：对话消息流。
- 当会话由健康事件触发时，在第一条消息上方插入“健康上下文卡”：触发时间、心率/血氧变化、来源设备、用户授权说明。
- 底部：文本框、语音按钮和快捷回应。输入区使用轻量液态玻璃，键盘弹出后隐藏底部导航。
- 空闲状态：展示一张较大的小云形象和 3 个自然入口，例如“陪我聊聊”“记录心情”“看看今天状态”。

不能把 LuminaAndroid 整页直接照搬；可复用会话接口、流式回复、历史记录、语音能力、角色资源和状态模型。

### 4.4 关怀

“关怀”不是第二个聊天页，而是小云主动行为的记录与控制中心。

- 顶部展示待处理事项，例如“昨晚血氧偏低后尚未回访”。
- 主体为按时间排序的关怀时间线：身体变化、手表震动、用户回应、AI 对话、后续提醒。
- 每条事件显示明确来源：心率变化、血氧变化、用户心情、久坐、闹钟或手动发起。
- 事件详情可以“继续和小云聊”“设为已处理”“关闭同类提醒”。
- 设置区控制触发类型、敏感度、安静时段、振动方式、是否把健康数据提供给 AI。

### 4.5 设备

- 顶部设备卡：手表渲染图、名称、连接状态、电量、同步时间和立即同步。
- 唯一 ID：扫码绑定或输入 ID；默认脱敏显示；解绑与转移设备需要二次确认。
- 闹钟：查看全部、添加、编辑、同步状态，明确显示“x/15”。
- 小云形象：选择对话和关怀时出现的角色外观。
- 手表皮肤/表盘：改变手表端界面主题，与“小云形象”分开，避免概念混淆。
- 其他设置：通知、声音与振动、健康监测、固件、存储、帮助。

## 5. 心率与血氧页面重设计

目标是参考 Apple Watch 对健康数据的克制、准确和动态感，但形成 LuminaWatch 自己的白色视觉语言。

### 5.1 共同结构

```text
顶部返回 + 指标名称
最近测量的大号数值与状态
日 / 周 / 月 / 年液态滑动选择器
可拖动读取的趋势图
关键统计：范围、均值、最低/最高、有效记录
小云洞察卡
异常事件列表
了解该指标 / 数据来源 / 免责声明
```

### 5.2 心率

- 页面主色仍是白色，指标强调色使用克制的珊瑚红，不把整张卡染红。
- 最近值使用超大数字和等宽数字特性；单位“次/分”降低一级。
- 图表由原来的静态粗柱改为点线/区间图：
  - 日视图显示散点与时间轴；
  - 周/月视图显示每日范围和静息均值；
  - 拖动时出现垂直游标、数值浮层和轻触觉反馈；
  - 异常点使用空心标记加文字，不只用颜色。
- 活动、休息和情绪相关记录可以在图表底部作为事件标记，帮助解释变化。
- 小云洞察使用谨慎语言，例如“这段时间比你近期静息水平高”，禁止直接写医学诊断。

### 5.3 血氧

- 指标强调色使用低饱和青蓝，保持与心率清楚区分。
- 最近值显示百分比、测量时间和测量质量。
- 日视图用离散测量点与轻量面积图，不能用连续实时曲线暗示设备拥有并不存在的连续数据。
- 周/月视图显示区间、有效测量次数和偏低记录。
- 数据缺失时显示“暂无有效记录 + 如何正确佩戴”，而不是空白图。

### 5.4 页面质感

- 数据页主要使用白底、细分隔、极浅暖灰分区和大留白。
- 图表本身不做玻璃折射，保证线条和数值准确可读。
- 玻璃只用于时间范围滑块、图表 tooltip、浮动操作和底部导航。
- 页面一次只突出一个主要数字，避免多个巨大数字争夺注意力。

## 6. 心理状态记录

参考用户提供的 Apple Watch 心理状态流程，但不使用其花朵造型、配色或页面排版。

### 记录流程

1. 选择“此刻感受”或“今日整体心情”。
2. 拖动情绪连续轴，从非常不愉快到非常愉快。
3. 选择 1～3 个情绪词，例如平静、焦虑、开心、疲惫。
4. 选择可能影响因素，例如工作、学习、家庭、睡眠、健康。
5. 可选添加文字、语音，或转入小云对话。
6. 保存后生成当天的“小云心情光团”。

### 原创视觉表达

- 不使用 Apple 的情绪花朵，改为 **“小云心情光团”**：云朵轮廓、呼吸光和柔和涟漪随情绪变化。
- 暖色代表积极但不等同于“正确”，冷灰蓝代表低落但不等同于“危险”。
- 月历用不同轮廓、密度和标签共同表达，不能只靠颜色。
- 单日详情显示情绪词、影响因素、相关身体数据和当日对话摘要。
- 只做记录、趋势和陪伴，不给出心理疾病诊断。

### “情绪云”在 Android 中的实现方案

用户提到的能力确实存在，但需要区分两个概念：

1. `MaterialTheme.shapes` 主要控制卡片、按钮等组件的圆角体系，不能直接生成会连续变形的云朵。
2. 真正适合本功能的是 AndroidX 的 `graphics-shapes`：使用 `RoundedPolygon` 定义轮廓，用 `Morph` 在两个轮廓之间连续插值，再转为 Compose `Path` 绘制或裁切。

Material 3 另有 `MaterialShapes` 预设形状集合，可提供 Cookie、Sunny、Pill 等 `RoundedPolygon`，但它属于 Material 3 Expressive API，且预设形状不是小云的最终品牌轮廓。当前项目显式使用 `material3:1.5.0-alpha10`，而 `MaterialShapes` 从 `1.5.0-beta01` 才加入，因此本项目更稳妥的路线是独立使用稳定版 `androidx.graphics:graphics-shapes:1.0.1`，不为了一个图形组件强行升级整套 Material 3。

#### 形状设计

- 设计 5 个基础云形：低落、偏低、平静、愉快、高能量。
- 每个基础云形使用相同数量、相同顺序的采样顶点，例如 12 或 16 个点，保证 Morph 过渡稳定。
- 用 `CornerRounding` 和较高 `smoothing` 把多边形变为柔软云团，不出现尖角。
- 情绪值不是直接切换图片，而是作为 `0f..1f` 的连续参数驱动相邻云形之间的 `Morph`。
- 情绪强度控制云朵起伏幅度，能量/唤醒度控制呼吸速度；颜色只做辅助，不单独代表心理状态。

#### 视觉层次

```text
外层云轮廓：RoundedPolygon + Morph
├─ 柔和渐变填充：暖杏 / 暖灰 / 青灰蓝
├─ 内层缩放云轮廓：低透明高光
├─ 中心柔光：RadialGradient
└─ 轻微呼吸：scale 0.98～1.02 + alpha 变化
```

情绪云本身使用 Compose Canvas 绘制，不叠加重度实时玻璃折射。页面的滑块、浮层和确认按钮仍可使用液态玻璃，从而保持清晰度与性能。

#### 动态规则

- 用户拖动情绪滑块时，云形、颜色和标签必须实时跟手变化。
- 松手后用弹簧动画吸附到最近的语义区间，但保存的数据仍保留连续值。
- 形变动画建议 250～400ms；空闲呼吸周期 3～5 秒，幅度很小。
- 开启系统“减少动态效果”后停止循环呼吸，只保留一次短过渡。
- 月历缩略图使用预先计算/缓存的静态 Path，不在每个日期格同时播放 Morph 动画。

#### 推荐结论

最终采用：**自定义小云 RoundedPolygon + graphics-shapes Morph + Compose Canvas**。Material 3 的 `MaterialShapes` 只用来做原型和参数参考，不直接拿某个 Cookie 预设冒充小云品牌形象。

## 7. 小云形象资产复用方案

### 已确认的现有资源

- `LuminaCross/shared/src/commonMain/assets/common/emoji_cloud/` 中有完整的小云表情集合，包含微笑、平静、焦虑、委屈、心动、思考、加油等几十种状态。
- `LuminaCross/shared/src/commonMain/assets/` 中还有 `Interact.gif`、`Relax.gif`、`Sit.gif` 等动态资源。
- `LuminaAndroid/app/src/main/res/drawable/` 中已有少量小云 PNG，可参考其 Android 资源接入方式。

### 使用映射

| 场景 | 建议资源状态 | 呈现方式 |
|---|---|---|
| 小云对话空闲页 | 微笑、平静、思考 | 120～160dp 主形象，轻微呼吸动效 |
| 小云消息头像 | 平静/微笑 | 28～36dp，统一暖灰底圆形容器 |
| 健康变化发起关怀 | 关心、焦虑，但不惊恐 | 手表端短动画 + APP 关怀卡 |
| 用户回复“我没事” | 放松、点赞 | 快速反馈，不打断用户 |
| 用户需要鼓励 | 加油、心动、微笑 | 对话结尾或回访卡 |
| 心理状态记录 | 平静、委屈、开心等 | 作为情绪词辅助，不替代文字 |
| 形象设置 | 全量静态表情和动态预览 | 网格选择 + 大图预览 |

### 资产规范

- 原始资源先做清单、尺寸、透明通道、版权和命名检查，再复制到 LuminaWatch。
- 优先转为 WebP 并保留透明背景；列表缩略图使用小尺寸版本，避免直接加载大图。
- 白色小云在白底上需放入淡暖灰/淡陶土色背景或增加极轻轮廓，不允许轮廓消失。
- 动态 GIF 只用于对话首屏和形象预览，不在长列表中同时播放。
- 同一情绪在手表和 APP 中使用同一个语义映射，避免“手表焦虑、手机却微笑”。

## 8. 主动关怀交互

### 触发逻辑（产品层）

- 心率相对个人近期基线明显升高或降低；
- 血氧出现有效偏低记录；
- 用户记录明显负向心理状态；
- 长时间静止、闹钟或计划到时；
- 用户手动请求小云关怀。

正式算法阈值需结合硬件能力、数据质量和专业意见确认。本方案不把单次测量直接定义为异常。

### 用户体验

1. 手表短震动，小云出现：“我注意到你的心率比平时高一点，现在还好吗？”
2. 手表提供“没事”“刚运动”“有点难受”“和你聊聊”四个大触控选项，并支持语音。
3. 若选择聊天，手机 APP 的小云页自动带入此次事件上下文；用户能清楚看到共享了哪些数据。
4. 结束后询问是否稍后回访，例如 10 分钟、30 分钟或不回访。
5. 事件进入关怀时间线，允许用户删除或关闭同类提醒。

### 安全边界

- 避免“你有疾病”等诊断语句，统一表达为“检测到变化”“建议复测”“如持续不适请寻求专业帮助”。
- 明确区分“传感器提示”“AI 陪伴建议”和“紧急求助”。
- 安静时段默认只保留高优先级振动；用户可完全关闭主动对话。

## 9. 闹钟功能

### 入口

- 今日页：只显示下一闹钟和快捷开关。
- 设备页：进入完整闹钟列表和编辑页。
- 小云对话：允许自然语言创建，但提交前必须弹出结构化确认卡。

### 规则

- 最多 15 个；标题区持续显示“已使用 x/15”。
- 达到 15 个后禁用新增按钮，并说明需要删除或关闭现有闹钟；关闭是否占用名额需产品统一，建议“存在即占名额”。
- 字段包括时间、重复日期、标签、振动/声音、稍后提醒、小云播报、是否同步至手表。
- 新建、修改和删除必须显示同步状态：待同步、同步中、已同步、失败可重试。
- 删除支持短时间撤销，批量删除需要二次确认。

## 10. 设备绑定、形象与皮肤

### 唯一 ID 绑定

- 支持扫码与手动输入。
- 绑定流程：识别设备 → 核对名称/型号/尾号 → 用户确认 → 同步初始化。
- 默认只显示 ID 尾号；复制完整 ID 需要再次操作。
- 更换或解绑设备前提示健康记录、闹钟和皮肤的影响。

### 两类个性化必须区分

- **小云形象**：影响 APP 对话头像、主动关怀表情和手表对话形象。
- **手表皮肤/表盘**：影响时间、健康组件和手表首页的视觉主题。

形象页可复用 Lumina 的小云图片；表盘皮肤则使用专门预览图，不混用头像资源。

## 11. 视觉系统

### 11.1 颜色

整体以白色为主，不使用紫色作为品牌色。

| Token | 建议色值 | 用途 |
|---|---|---|
| `Background` | `#F7F6F3` | 页面底色，带一点暖意而非冷灰 |
| `Surface` | `#FFFFFF` | 数据卡、对话卡、设置卡 |
| `TextPrimary` | `#1F1F1D` | 标题、关键数字、主图标 |
| `TextSecondary` | `#6F6C67` | 解释、单位、时间 |
| `ClaudeWarm` | `#D97757` | 品牌按钮、选中标记、暖色强调 |
| `ClaudeWarmSoft` | `#F4E4DC` | 次级按钮、标签背景 |
| `ActionBlack` | `#171716` | 高权重主按钮、中央小云按钮 |
| `Heart` | `#D85B5B` | 心率数据，不作为通用错误色 |
| `Oxygen` | `#3F9BA8` | 血氧数据 |
| `Warning` | `#C86B32` | 注意/复测提醒 |
| `Danger` | `#B3261E` | 真正危险或删除操作 |

黑色按钮只用于页面唯一主操作，例如“开始对话”“保存记录”“绑定手表”；普通操作使用暖橙或白底描边，防止全页过重。

### 11.2 字体与数字

- 使用 Android 系统中文字体体系，标题 600～700，正文 400，标签 500。
- 大号健康数字启用等宽数字特性，避免数值变化导致跳动。
- 字阶建议：32/28/24/20/17/15/13sp；正文不低于 14sp。
- 支持系统字体缩放，关键标签不允许只靠省略号隐藏。

### 11.3 圆角、阴影与间距

- 页面水平边距 20dp；小屏可降至 16dp。
- 卡片圆角 24dp；小卡 18dp；按钮 16dp 或胶囊形。
- 使用 4/8dp 间距体系；章节间距 24～32dp。
- 阴影极轻，以边界和留白建立层级；数据页避免厚重悬浮卡。

### 11.4 图标

- 统一使用圆角线性图标，默认 2dp 左右描边。
- 选中时允许局部填充，但同一层级不能混用多套风格。
- 不用 Emoji 代替功能图标；小云表情是角色资产，不属于功能图标。
- 所有图标按钮触控区域至少 48×48dp，并提供文字或无障碍描述。

## 12. 液态玻璃使用规范

液态玻璃用于“交互层”，不用于承载大量文字和关键健康数据。

### 使用

- 底部导航栏与可拖动选中指示器；
- 日/周/月/年选择器；
- 图表拖动后的数值浮层；
- 小云输入区、底部弹窗、确认弹窗；
- 少量高权重悬浮按钮。

### 不使用

- 心率/血氧图表背景；
- 长列表中的每张卡片；
- 大段说明文字；
- 危险提示的唯一视觉方式。

### 技术边界

- Android 13+ 提供完整折射与 RuntimeShader；Android 12 使用模糊与高光；更低版本使用实体半透明降级。
- 基于 Backdrop 2.0.0 实现时，玻璃上叠玻璃必须使用 `exportedBackdrop`，防止循环绘制造成崩溃。
- 长列表优先实体卡或 `drawPlainBackdrop`，避免大量 GPU 图层。
- 动效 150～300ms，可被手势打断，并尊重系统“减少动态效果”设置。

## 13. 关键交互流程

### A. 从健康变化到小云对话

```text
手表确认有效变化
→ 震动 + 小云短问句
→ 用户快捷回应
→ 需要交流时打开中央“小云”页
→ 顶部展示本次健康上下文卡
→ 对话结束
→ 是否稍后回访
→ 写入关怀时间线
```

### B. 从心理记录到对话

```text
健康 → 心理状态 → 记录当下
→ 拖动情绪轴 → 选择情绪词/影响因素
→ 保存
→ 可选“和小云聊聊”
→ 对话自动引用本次记录，但需用户明确授权
```

### C. 创建闹钟

```text
今日快捷入口 / 设备闹钟 / 小云自然语言
→ 新建闹钟
→ 校验是否达到 15 个
→ 用户确认
→ 本地保存并同步手表
→ 显示同步结果与失败重试
```

### D. 更换形象

```text
设备 → 小云形象
→ 浏览静态/动态形象
→ 大图预览对话与手表效果
→ 应用
→ 同步手表
```

## 16. 验收标准

- 用户无需进入二级页即可从底部中央打开小云对话。
- 底部导航支持点击和拖动，反馈跟手且不与系统返回手势冲突。
- 用户能在 3 次点击内查看心率或血氧详情。
- 图表可拖动读取具体值，日/周/月/年切换状态清晰。
- 关怀事件能说明“为什么触发、用了什么数据、后来做了什么”。
- 第 16 个闹钟无法被创建，并得到明确原因和解决办法。
- 小云形象与手表皮肤概念清晰、入口明确。
- 小云图片在白底和暖灰底上均清晰，不出现白色轮廓消失。
- 所有关键触控区至少 48×48dp，正文对比度达到 WCAG AA。
- 低版本 Android 即使没有完整玻璃效果，功能和信息仍完整可用。
