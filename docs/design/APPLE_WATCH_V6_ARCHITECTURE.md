# LuminaWatch 全量改版架构方案 V6（实施中）

日期：2026-10-22  
设计基准：用户提供的 Apple Watch 手机 App 录屏 `1.mp4`、`2.mp4` 及现有 LuminaWatch 功能。  
本稿取代先前包含 Backdrop／液态玻璃底栏的 V4、V5 方案。那些旧稿不再作为实施依据。

## 1. 目标与边界

目标是以 Apple Watch 手机 App 的**信息层级、版式、密度和导航行为**为视觉基准，重新组织 LuminaWatch 的整个手机端界面；默认浅色，并提供作用于**所有页面**的深色切换。不是给旧页面换圆角、阴影或一层玻璃。

必须保留闹钟、设备状态与绑定入口、表盘预览、小云形象、健康与活动、心情三步记录与月历、对话与记忆、关怀与提醒、隐私设置、已有本地数据。没有接入的手表同步、传感器与云服务继续明确标注，不能做假成功反馈。心情页原有云朵动画、滑块、情绪颜色和记录逻辑保留，但页面框架要纳入新版。

不使用 Backdrop 2.0.0 的模糊、折射、透镜、玻璃高光；底栏也没有拖动放大块。可以保留依赖直到无调用后安全清理，但最终可见 UI 不得出现液态玻璃。

“一比一”用于结构、比例、对齐和交互层级；文字、表盘图与品牌资源使用小云自己的内容，不把苹果未实现的功能伪装成可用。

## 2. 导航与页面架构

```text
一级：我的手表 | 表盘图库 | 发现
我的手表
  ├─ 所有手表／设备状态／绑定
  ├─ 我的表盘 → 表盘图库
  ├─ 手表设置 → 闹钟、连接与同步、小云形象、个人与隐私
  └─ 健康与陪伴 → 健康、心情、聊天、关怀
表盘图库
  ├─ 当前预览（仅手机）
  └─ 全部本地表盘（现有 3 款；无空分类）
发现
  ├─ 现在开始 → 小云、心情、月历、健康
  ├─ 了解更多 → 关怀、对话与记忆
  └─ 今日总览
```

一级页保留紧凑底栏，二级详情采用顶部返回；返回必须回到原位置，不清除列表、搜索和表单状态。原 `Screen` 路由只调整归属和呈现，不删除业务入口。

## 3. 全局视觉规格

| 项目 | 浅色（默认） | 深色 |
|---|---|---|
| 页面背景 | 接近白色 `#FFFFFF` | 接近黑色 `#000000` |
| 分组底 | 浅灰 `#F2F2F7` | 深灰 `#1C1C1E` |
| 主文字 | `#1C1C1E` | `#F5F5F7` |
| 次文字 | `#636366` | `#AEAEB2` |
| 分隔线 | `#D1D1D6` | `#38383A` |
| 操作强调 | 小云橙；仅用于可操作文字、状态 | 同语义、单独校验对比度 |

布局采用 4/8dp 节奏：页面水平留白 20dp 左右；一级大标题约 32–34sp，组标题 18–20sp，行标题 16–17sp，说明 12–14sp。设置组使用连续圆角组容器与细分割线，不把每行拆成一张悬浮卡。行高由内容决定，交互热区至少 48dp。搜索、表盘、内容列表和底栏按录屏相对比例校对，不盲目复用旧页面数值。

### 底部导航（重点）

- 只有“我的手表／表盘图库／发现”三项，图标与文字上下排列。
- 居中、紧凑；目标宽度约屏宽 65–70%，高度约 52–58dp；三项各自保留 ≥48dp 高、≥72dp 宽热区。
- 实体底色，浅色为浅灰、深色为炭灰。选中态是**静态实色圆角区域**；没有毛玻璃、折射、拖动透镜、果冻形变、浮夸阴影。
- 只在一级页出现，遵守系统手势区；滚动内容必须留足底部空间，不能遮挡最后一行。
- 切页可有 150–200ms 的轻微淡入，但不改变控件尺寸，尊重系统减少动画设置。

### 全局深浅切换

“个人与隐私 → 外观 → 深色外观”作为唯一手动开关，默认关闭，并持久化。切换后首页、底栏、二级页、弹窗、表单、图标、分隔线、状态栏和导航栏同时更新；不再保留“只切底栏颜色”的旧开关。深浅两版布局尺寸完全一致，心情页仅保留情绪色作为局部视觉元素，不让浅色背景破坏深色正文可读性。必须逐页检查硬编码颜色。

## 5. 技术实施架构

### 小云表情表盘（新增设计要求）

项目已经有 `CloudAvatars` 对应的 **50 款小云表情 PNG**。优先复用这一套原始资源，而不是重新画表情或用系统 emoji。它们是透明素材，可嵌入表盘预览；实施前须逐张检查缩小时的清晰度与边缘裁切。

- 表盘正面以**时间为第一视觉层**，小云表情放在中央偏下或时间下方，不盖住数字；日期可放角落。没有真实数据来源时，不在预览里摆出貌似实时的心率／步数。
- “我的表盘”横向列表里显示一张带小云的完整手表预览；点开“编辑表盘”后，先选现有配色（纯白／珊瑚／深色），再在横向表情列表中选小云表情。选中态有文字和勾选，不只靠颜色。
- 默认选项为“跟随小云形象”，即沿用 App 当前 `avatarId`；若用户为表盘单独指定表情，则保存独立的 `faceAvatarId`。提供“恢复跟随”的入口，避免更改 App 形象时表盘莫名不变。
- 表盘预览的浅／深模式由**表盘自身主题**决定；App 的全局深浅切换只改变图库容器，不能偷偷改用户选定的表盘配色。
- 目前只在手机端预览并保存配置，**不得显示“已同步至手表”**。将来接入真实手表后，再定义图片下发、尺寸适配、电量和动画能力；现阶段不宣称真机支持动态表情。
- 验收：50 款可左右浏览、选择后主预览即时更新，重启仍保留；文字始终可读，表情不被表盘圆角裁切；浅／深 App 主题下均正常。

1. **主题层**：在 `AppStore` 增加独立的全局外观偏好（默认浅色），在 `LuminaWatchTheme` 建立语义色映射；不拿旧 `bottomBarDark` 值推断用户想要全局深色。状态栏与系统导航栏随主题更新。
2. **组件层**：统一页面容器、一级标题、二级返回、分组、设置行、分割线、按钮、搜索框、空状态、底栏；这些组件只读语义色，不写固定白／黑值。玻璃组件逐个替换为实体表面，不在业务层重复实现。
3. **页面层**：先改三个一级入口，再改各二级页面族；路由与 `AppStore` 数据操作保持原路径。对于原流程，做 UI 迁移而非重新开发数据逻辑。
4. **验证层**：每个页面浅／深两张同尺寸截图，与视频关键帧并排检查层级、比例、间距、截断及按钮位置；再做功能与持久化回归。

## 6. 分批交付及通过条件

| 批次 | 内容 | 交付门槛 |
|---|---|---|
| A：基座 | 全局主题、系统栏、无玻璃紧凑底栏、共用页面组件 | 切换后所有一级页与弹窗不出现浅色孤岛；底栏不遮挡；无 Backdrop 可见效果 |
| B：一级页 | 我的手表、表盘图库、发现按录屏重排 | 三页实机截图与参考关键帧对照；搜索、表盘持久化、入口正常 |
| C：核心功能 | 健康、心情三步／月历、对话、关怀 | 原数据不丢；同日多条心情可见；编辑、保存、返回可回归 |
| D：设置与设备 | 闹钟、设备／绑定、形象、记忆、隐私及其弹窗 | 所有开关与表单功能等价；未接入状态不误导 |
| E：全量验收 | 两套主题、大小屏、无障碍、冷启动和安装包 | 无崩溃；每个路由截图；列表末项可见；重启后主题与业务数据保留 |

每批都要先给**视觉对照**，再给可安装版本；若与参考差异明显，先修布局，不靠改颜色宣称完成。项目现有“手机打不开 App”的问题另列启动验收：记录设备型号／Android 版本／崩溃日志，在得到真实设备信息前不能宣称已修好。

## 7. 明确不做

不恢复液态玻璃或放大透镜；不制作虚假的多手表同步、传感器曲线或云端成功提示；不重置已有数据；不把三入口改回五入口；不以静态设计稿代替可运行页面验收。
