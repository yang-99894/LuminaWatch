# LuminaWatch 白色版重设计 V4：按 Apple Watch 手机 App 的结构施工

> 状态：设计与验收规格，**不代表已实现**。2026-10-21。此文替代此前只调整白底、卡片、玻璃效果的施工顺序；现有数据、功能、包名与签名均保留。参考来自用户提供的 `1.mp4`、`2.mp4` 和项目内 `docs/design/reference/` 截帧。参考录屏是深色界面；本项目按用户决定做**白色版本**，复用其信息架构、比例、密度与交互逻辑，不复制 Apple 的图标、表盘资产或商标。

## 0. 为什么“改了但看不出来”

目前改动集中在颜色、卡片材质、标题和局部动效；主要几何关系没有变。`我的手表`仍把巨大表盘卡放在屏幕中间，使设置行下沉；`表盘图库`仍是大面积暖色 Hero + 普通列表；底栏是**左右仅 14dp 外边距、78dp 高的近全宽胶囊**，加上大块等宽选中背景。Apple 录屏首屏则是紧凑设备标题 → 搜索 → 横向表盘预览 → 紧凑设置组；底栏是**居中、窄、薄、悬浮**的三标签控件。必须先重排页面，再谈玻璃和动效。

可直接对照：Apple `docs/design/reference/v1/f_001.jpg`；当前 `docs/design/baseline/phaseC_watch_bottom.png`。Apple 参考图底栏的视觉宽度约为屏宽 55% 左右；当前为 90% 以上。这里的百分比是截图观察值，不是 Apple 官方尺寸规范。

## 1. 产品映射：Apple 有什么，我们有什么

| Apple Watch 手机 App 的主要能力 / 入口 | LuminaWatch 现状 | V4 处理 |
|---|---|---|
| 我的手表：设备名、所有手表、搜索、我的表盘、成组设置 | 已有三栏和设备首页，但版式过大、信息密度低 | 保留入口，重排首屏；仅显示真实设备状态 |
| 我的表盘：横向预览、编辑、查看某款表盘 | 有 3 款本地主题预览与 `face_theme` 持久化 | 预览缩小并横滑；点击进真实详情/预览；“应用”只作用于 App 预览，明确未下发手表 |
| 表盘图库：可浏览的图像网格和详情 | 只有 3 款主题，现为大 Hero + 列表 | 用 Apple 式视觉网格呈现真实 3 款；不造假分类或“在线下载” |
| 发现：编辑推荐/功能介绍内容流 | 有“现在开始 / 了解更多 / 今日总览” | 改成图文内容行、章节与分隔线；仅链接到可用功能 |
| 设备设置：通知、显示、App 等 watchOS 设置 | 本项目有闹钟、绑定、形象、隐私、健康、心情、小云、关怀 | 用 Apple 式分组设置行组织本项目真实能力；不凭空增加 watchOS 开关 |
| 底部三栏：我的手表 / 表盘图库 / 发现 | 同名三栏，但外形和尺寸差很多 | 底栏重做为窄浮动胶囊；一级页保留各自滚动位置 |
| 手表配对、表盘下发、实时同步 | 目前没有真正 BLE/云端链路 | 显示“本地预览 / 未连接”；不把假按钮包装成已完成能力。真正接入另立项目 |

原有健康、心情月历、三步心情记录、问卷、小云对话、关怀、闹钟、隐私等**不能删**。它们是 LuminaWatch 的功能内容，重新放进符合 Apple 设置和详情页层级的界面，而不是把 Apple 的功能名称强行替换我们的功能。

## 2. 视觉系统：白色版 Apple 式布局，不是全屏玻璃

- 页面：暖中性的近白底；文字黑/深灰；次要字灰；蓝色只负责链接和系统动作。橙色只用于小云品牌点缀和功能图标，不在所有设置行铺大面积橙底。
- 一级标题与导航：一级页大标题；二级页小型返回按钮 + 居中标题。滚动时标题可收起成紧凑导航栏。真实设备名可作首页标题，但无绑定时显示“我的手表”。
- 内容边距：常规水平 16–20dp；标题、搜索、表盘轨道、设置组左缘统一。控件视觉尺寸按同一基线缩放，不能某页 24dp、另一页 40dp。
- 设置组：白/近白实体圆角容器，细分隔线、轻边界；行高一般 52–64dp（含副标题时允许增高）；组间 20–28dp。内容区不要大量模糊、投影、玻璃边。
- 表盘图像：作为内容主角，使用真实可辨的预览图/自绘表盘。卡片去掉大面积空白色块与夸张阴影；横向相邻预览露出一部分，提示可滑动。
- 玻璃只用在导航、必要浮层/弹窗。底栏材料应让滚动内容从背后透出，同时保证图标文字可读；不可把每张设置卡都做液态玻璃。
- 设计 token 先集中定义后复用：`pageHorizontal=20dp`、`groupRadius=18–22dp`、`rowMinHeight=54dp`、`sectionGap=24dp`、`primaryText=#1C1C1E`、`secondaryText=#6E6E73`。这些是 Android 白色稿的起始值，须以同尺寸截图对照微调。

## 3. 底部导航栏——P0，先做静态尺寸，再做果冻动效

### 3.1 形状与位置

在宽 360dp 的手机上，底栏**视觉容器宽 216–232dp，高 54–58dp**，水平居中。不能再用 `.fillMaxWidth()` 加 14dp 外边距，也不能维持 78dp 高。三个标签各占容器约 1/3；图标 20–22dp，标签 10–11sp，图标与标签间 2dp。选中玻璃小胶囊约 68–76dp 宽、46–50dp 高，不得占据整块 78dp 高的大卡。底部与系统手势区间隔约 8–12dp，由系统 `WindowInsets` 计算，不能写死到屏幕底边。适配较窄/较宽屏：容器宽度以 `min(max(屏宽 × 0.60, 216dp), 252dp)` 为起点；实际标签测量若不够，应让容器略增宽而不截字。

视觉示意（非像素图）：

```text
页面内容在背后继续滚动
              ╭─────────────────────────────╮
              │  ▣           ◉          ◇   │
              │ 我的手表     表盘图库       发现 │
              ╰─────────────────────────────╯
                       系统手势区域
```

外层胶囊透明白/中性灰，低强度背景模糊、0.5–1dp 明亮边、高光与极轻阴影。选中指示器是**内部小透镜**，不使用黑色大块，也不固定铺满整栏 1/3 的高对比灰卡。白色页面下仍须能看清容器边界，不能透明到消失；不要依赖橙色表示选中。

### 3.2 状态与交互

| 状态 | 视觉 / 行为 |
|---|---|
| 静止 | 当前图标和文字深色，未选中中灰；透镜停在当前标签下；整栏保持窄薄。 |
| 按下 | 触点所在透镜轻微放大和提亮，建议峰值 `1.04–1.08×`；其余标签不整体变大。 |
| 横向拖动 | 透镜跟手连续移动；拉长只在拖动中发生，X 向上限约 `1.10–1.14×`，Y 向轻微压缩；跨标签中心时提供一次轻触觉反馈。 |
| 松手 | 按距离+有限速度偏置吸附最近标签，`220–320ms` 弹簧回弹；支持立即中断、反向拖动。 |
| 点击非当前标签 | 透镜滑向目标，同时切换页；不出现先跳页后跳透镜或灰块残影。 |
| 长按/无障碍 | 拖动不是唯一入口；每个标签必须可单击。TalkBack 报出标签名与选中状态。减少动态效果时关闭拉伸，保留短位移或直接切换。 |

点击与拖动不得互相抢手势；拖动启动要有触摸 slop，微小移动仍按点击处理。视觉层尺寸小，但**每个标签的实际命中区至少 48dp 高**。玻璃捕获层不能把自身再次纳入背景采样。Android 12 以下无实时模糊时用同样几何、半透明白色实体和细边界降级，不能用黑色实心条替代。

### 3.3 实施定位与验收

当前实现位于 `app/src/main/java/com/pointerwander/luminawatch/ui/GlassBottomBar.kt`，现在是 `fillMaxWidth().height(78.dp)`、三个等宽大槽位和按单帧 `dragImpulse` 算的拉伸；优先重构尺寸、槽位和选中指示器的状态机，再处理 Backdrop 参数。`AppShell.kt` 的底部内容留白目前按大底栏设为 120dp，新尺寸完成后同步重算，内容滚动到底既不被遮住，也不能空出一大截。不要因为有现成液态玻璃模板就整套照搬；本项目应以现有 Backdrop 版本为准，单独验证升级兼容性。

验收必须提供：同一 360dp 模拟器上 Apple 参考截帧 / 修改前 / 修改后并排图，标出底栏左右边、顶部、底部与高度；底栏总宽明显小于屏宽 70%，高不超过 60dp。另交 60fps 拖动录屏，连续左→中→右→左、慢拖、快甩、点击切换、半途反向；一轮后选中页、透镜位置、图标状态一致。不能只提交编译通过或静态截图。

## 4. 逐页施工清单

| 页面族 | 必须改变的布局 | 必须保留的功能 / 验收 |
|---|---|---|
| 我的手表首页 | 对照 `reference/v1/f_001.jpg`：顶端所有手表小胶囊、紧凑大标题、薄搜索框、横向真实表盘缩略图、紧贴其后的分组设置行。首屏能看见设置组前几行；不再让大表盘卡占半屏。 | 所有手表弹层、搜索过滤、3 款预览主题、闹钟/连接/形象/隐私/健康/心情/小云/关怀入口全部可达。 |
| 表盘图库 | 对照 `reference/v2/`：以视觉预览为主体的两列网格/横向精选；3 款真实主题对应 3 张图，不用巨大空白 Hero + 普通文字行，也不伪造更多表盘。 | 选择主题后即时更新首页预览，强停重启仍保留；明确“仅 App 预览，未下发手表”。 |
| 发现 | 对照 `reference/v1/f_081.jpg`：章节标题、方形图像/插画缩略图、标题+说明、细分隔线的编辑式列表。 | 每条内容进真实页面；无功能的项目不出现在列表里。 |
| 二级页通用 | 小标题导航、返回路径明确、设置分组和白色实体行；取消通篇过大的卡片、深重阴影、黑色大按钮。 | 滚动、系统返回、弹窗、状态恢复；首屏不被底栏遮挡，二级页默认无底栏。 |
| 健康 / 心情月历 / 问卷 | 读数先行、分组紧凑；月历日期格有清晰边界和云缩略图/数量徽标；问卷内容按步骤排版。 | 指标来源不能伪造；心情按选定日期保存，返回月历即时显示，同日多条不覆盖；问卷结果及非诊断说明保留。 |
| 心情记录 | **保留现有浅色情绪背景、300dp 分层云、滑块、色彩映射、三步流程**；仅导航、字阶、边距、步骤进度和 CTA 对齐。不要改成白底圆玻璃云。 | 云动效、词语/因素/备注、保存及月历日期回填行为不变。 |
| 小云 / 关怀 / 闹钟 / 隐私 / 绑定 / 形象 | 对话页保持消息流；关怀用时间线；闹钟与设置用分组列表/编辑页；形象用整套角色横滑选择而非只展示两个。 | 原有本地数据、开关、删除/撤销、头像选择持久化；未连接手表的地方准确提示。 |

## 5. 分阶段执行，避免再次“看似改完”

1. **P0 先出视觉对照稿，不写全量代码**：360dp Android 同屏静态稿，包含我的手表首屏、表盘图库首屏、发现首屏、底栏静止/选中/拖动态、心情记录 1/3。提交参考帧/旧版/新版三列图。若底栏宽高、表盘占比、首屏设置行数量不达标，不进入下一阶段。
2. **P1 壳层与底栏**：只改三栏、背景、页内留白、底栏交互。保持现有 route 和数据对象。验证点击/拖动/返回/滚动位置/横竖屏与 API 版本降级。
3. **P2 三个一级页**：按第 4 节逐页实施，每完成一页给固定截图；必须让用户在不看文字的情况下明显区分旧版与新版。设置入口一项不漏。
4. **P3 二级页**：先设备设置与闹钟，再健康/心情月历/问卷，再小云/关怀/隐私/形象。心情记录按“保持页”处理。
5. **P4 全链路回归**：从我的手表进入每个功能、保存、退出重启后复核。保留现有本地数据，不 reset，不改包名/签名；检测空状态、长文案、字体放大、TalkBack、低版本无模糊、真机帧率。

每阶段的完成定义不是“代码提交 / BUILD SUCCESSFUL”，而是：真实功能未退化 + 同屏截图几何对齐 + 录屏显示交互达到规格。第一批只要底栏和三大页不相似，应停下来修布局，不继续给旧页面刷材质。
